# 开发计划（ROADMAP）

- 前提假设：1 名开发（本人）+ AI 辅助，业余时间投入；工期按「周」给区间，含缓冲。
- 关键路径：**M1 → M2 → M3**。M4 可与 M3 并行或顺延；每个里程碑结束时都有可玩、可给朋友试的产物。

## 总览

| 里程碑 | 内容 | 工期 | 出口标准（验收） |
|---|---|---|---|
| M0 | 仓库与脚手架 | 0.5 周 | CI 绿灯，前后端 hello-socket 跑通 |
| M1 | 平台核心（房间/身份/聊天/重连） | 1–1.5 周 | 两浏览器开房互聊；刷新页面重连保座 |
| M2 | 游戏框架 + 忍者之夜灰盒可玩 | 2 周 | 4–8 人完整对局，裁判单测覆盖 ≥90% 分支 |
| M3 | 美术/动画/音频打磨 | 1.5–2 周 | 主题包换肤完整；中端手机 60fps；音频策略正确 |
| M4 | 第二款游戏（验证框架） | 1–1.5 周 | 零（或 <10%）框架改动接入新游戏 |
| M5 | 上线部署 | 0.5 周 | HTTPS 域名可访问，日志/备份/拨测就位 |

**MVP（M0–M3）预计 5–6 周**；含第二款游戏与上线约 **7–8 周**。

---

## M0 仓库与脚手架（0.5 周）

- [ ] `git init` + pnpm workspace 单仓多包（`apps/web`、`apps/server`、`packages/protocol`、`packages/games/*`）
- [ ] ESLint + Prettier + vitest + GitHub Actions（lint/test/build）
- [ ] 前后端 hello-socket 跑通，共享 `packages/protocol` 的 zod 消息类型
- [ ] 本地开发脚本：一条命令起前后端 + 热更新

**验收**：push 后 CI 全绿；本地打开页面能看到 socket 往返。

## M1 平台核心（1–1.5 周）

- [ ] 身份：昵称 + 头像（内置头像库选择），localStorage 持久化
- [ ] 房间：创建（生成邀请码）/ 凭码或链接加入 / 等待室（玩家列表、准备状态、房主开踢）
- [ ] 站点入口口令（环境变量开关）：将访问范围固定为朋友圈，呼应 DESIGN §12 版权定性
- [ ] 大厅页与平台壳视觉（夜之桌游馆主题 v1：布局 + 色板，不追求精修）
- [ ] 房内文字聊天 + 表情回应（限频、转义）
- [ ] 会话与重连：sessionToken、座位保留 90s、心跳、掉线提示
- [ ] 消息协议 v1 落地：`action/events/sync` + rev 序号（按 DESIGN §5.2）

**验收**：两个浏览器 + 一台手机开房互聊；任一端刷新后回到原座位；断网 60s 内重连不丢房间。

## M2 游戏框架 + 忍者之夜灰盒（2 周）★ 关键里程碑

- [ ] `packages/games/core`：`GameDefinition` 接口、事件定向、种子 RNG、事件日志（JSONL）
- [ ] 房间管理器接入游戏插件：阶段推进、服务端时钟、超时垫步
- [ ] **规则核对**：对照官方规则书（fgbradleys PDF）固化卡牌数据表与计分规则，产出 `docs/rules-night-of-ninja.md`
- [ ] 忍者之夜裁判：身份分发 → 轮抽 → 夜晚结算 → 回合/终局计分
- [ ] 灰盒客户端：桌面布局（座位环绕）、手牌、出牌/选目标交互，全部由 `legalActions` 驱动
- [ ] 测试：裁判表格驱动单测、视图泄露扫描测试、双客户端集成测试
- [ ] 开发用机器人（随机合法动作），用于凑桌测试与 soak

**验收**：4–8 人（可混机器人）完整对局至终局，全程裁判无错；人为断线一人对局不卡死；单测覆盖 ≥90% 分支。

## M3 美术/动画/音频打磨（1.5–2 周）

- [ ] 忍者之夜主题包：色板/字体/桌面纹理/卡背（花·影家纹）/卡面
- [ ] 动画清单落地（事件驱动）：发牌飞行、轮抽选牌上浮、出牌滑入、翻牌、手里剑刺杀 + 震屏、死亡灰化、全桌揭示瀑布、胜利演出（Lottie）
- [ ] canvas 粒子层：环境粒子（萤火/落樱）+ 事件爆发粒子；设备分级与低配模式
- [ ] AudioDirector：手势解锁、BGM 分阶段交叉淡化、SFX 集、ducking、按座位 pan、音量偏好
- [ ] 素材制作/收集：BGM 3–4 首、SFX ~15 个、卡面与纹样（来源策略按 DESIGN §4.4）
- [ ] `prefers-reduced-motion` 与低配模式降级路径

**验收**：完整对局在主题包下视觉/听觉成体系；中端手机稳 60fps；静音刷新后偏好保留；关动画模式全流程可玩。

## M4 第二款游戏（1–1.5 周）

- 候选（按验证框架不同维度的价值排序）：
  1. **情书 Love Letter**：2–4 人纯回合制 + 手牌隐藏，实现最简，验证「简单回合制」轴
  2. **阿瓦隆 Avalon**：5–10 人组队投票，验证「投票/任务阶段」轴，与朋友局调性最合
  3. 炸弹猫类：轻松向，抽牌堆风险轴
- [ ] 选定一款：裁判 + 主题包 + 规则页
- [ ] 记录框架改动点；若 >10% 说明抽象需返修

**验收**：新游戏从零接入 ≤1.5 周；框架无破坏性修改。

## M5 上线部署（0.5 周）

- [ ] Docker Compose（caddy + server + 静态托管）、域名与 HTTPS
- [ ] **部署地区决策**：国内访问（需备案）vs 海外节点/Cloudflare Tunnel —— 与朋友实际分布确认后定
- [ ] `/healthz`、pino 日志滚动、外部拨测、SQLite/replays 每日备份脚本
- [ ] 战绩统计 v1（SQLite，按昵称聚合）+ 首页游戏橱窗文案
- [ ] 给朋友的使用说明（一条链接开玩）

**验收**：手机浏览器从受邀链接到进入对局 ≤3 次点击；服务器重启仅影响当时对局（房间外无感）。

## Backlog（M5 之后，按朋友反馈排序）

- 观战模式与对局回放（事件日志已就绪，成本低、效果好）
- 第三款及更多游戏（璨宇/Codenames 词猜、一夜终极狼人）
- 账号体系（平滑迁移 localStorage 档案）、跨设备战绩
- PWA（添加到主屏）、快捷短语轮盘（替代语音的沟通增强）
- 管理面板：房间监控、踢房、广播维护通知
